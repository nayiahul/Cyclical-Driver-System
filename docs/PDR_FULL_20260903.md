## 1. 项目背景

### 1.1 业务痛点

个人投资者面对 A 股 5000+ 上市公司，存在三重结构性困难：
1. **信息过载**：每日公告/新闻/价格变动远超个人处理带宽，缺乏系统化压缩手段
2. **信号不可信**：财报指标(合同负债/营收/利润)存在低基数、周期性、一次性收益等失真模式，直接解读会误判（实证：恒瑞合同负债+371%实为环比-35%，CAL-001）
3. **无记忆闭环**：投资判断散落，无结构化记录 → 无法复盘"当时为什么判断、后来对不对"

### 1.2 行业现状与现存方案短板

| 方案类型 | 代表 | 短板 |
|---|---|---|
| 量化选股器 | 多因子/机器学习选股 | 黑箱、无解释、易过拟合；实证:本系统初版收益 85% 来自未来函数泄漏(PDR 归因) |
| 传统研报平台 | Wind/Choice/东财 | 信息堆砌, 无判断闭环, 不面向个人决策 |
| AI 对话分析 | LLM 单次问答 | 无数据治理、无记忆、无验证、易产生确认偏误 |

### 1.3 项目建设目标

> 从 5000+ A 股中，通过"数据可信 → 变化发现 → 状态识别 → 人工判断 → 复盘校准"闭环，为个人投资者生成**值得研究的标的池**（非买卖信号），并积累可复盘的**个人投资记忆**。

### 1.4 适用场景与边界

- 适用：月度级研究筛选、财报真空期资讯监控、个股深度核验、判断留痕复盘
- 边界（明确不做）：不自动交易、不预测行业拐点(实证三数据源失败)、不保证抓牛股(Winner Capture 1.06)、不替代人工行业判断

### 1.5 约束条件

- 数据须 PIT(Point-in-Time)治理——只用研究日真实可见信息
- 运行期 30 天冻结——不因单案例改模型
- 指标纪律——评价函数错误可判死有效模型(L5 恢复率 26.7%→50.2% 教训)

## 3. 设计思路

### 3.1 核心设计决策（含依据）

| 决策 | 依据 |
|---|---|
| PIT 数据治理为第一层 | PDR 归因: 旧收益 85% 为未来函数泄漏 |
| 状态标签(L/E)而非综合评分 | RPI 坍缩实证——加权评分制造伪精确 |
| 先验证后接入 | L5/E/P 每层均走 7 步验证链(假设→候选→历史→子类→人工→反事实→Shadow) |
| 运行期冻结 30 天 | 防"见一案例改一规则"污染样本 |
| 人工判断与机器状态分离(Overlay) | 恒瑞案例: 机器 A 级与人工 IGNORE 并行, 不互相覆盖 |
| 判断来源标注(AI_ASSISTED vs HUMAN) | Q3 归因准确性前提——区分"人错"与"AI框架错" |

### 3.2 非功能需求

- **可验证性**: 29+ 测试、manifest 归档、audit hash
- **可解释性**: Memo 每句可溯源(Evidence Trace)
- **防污染**: Shadow 模式(只观察不决策)、CAL 只指引不降权
- **可维护**: 运行期冻结协议、Issue 队列、Wishlist 机制

## 4. 系统架构

```
Internet/数据源
    ↓
XIS 信息基础设施 (event_scan E1-E18 + daily_collector + AnySearch)
    ↓
pit/ 数据治理层 (MarketData.as_of / FinancialData 披露日 / PITGuard)
    ↓
Growth OS 认知层
  ├─ L 生命周期 (state_machine, L0-L5, 范式参数化)
  ├─ E 认知 (expectation_state, E0-E3 + v2 Shadow 三维)
  ├─ P 产业 (paradigm_shadow, AI_OPTICAL P2, Shadow only)
  ├─ L5 错杀 (l5_recovery, 恢复率50.2%/错误率8.7%)
  └─ Radar 分配 (Growth 25 + Recovery 25, Radar-Quota)
    ↓
Output 层: Research Book (50 Memo) + Memo Engine (7模块)
    ↓
人工层: decision_cli (极简判断) → Ledger → Overlay (人机并行)
    ↓
学习层: Calibration Library (CAL-001..004, MAC-001) + 历史回填 100 条
```

核心链路: 扫描→Book→人工判断→Ledger→Overlay→T+30 校准
辅助链路: 事件采集、Golden Pit 模板、Reverse DCF、04 交易协议(人工执行)

## 5. 项目创新点

| 创新 | 解决原问题 | 收益 | 局限 |
|---|---|---|---|
| PIT 泄漏归因四基线 | 收益真假不分 | 量化 85% 泄漏 | 需定期重跑 |
| L×E 双轴状态机 | 单轴状态无法区分"变化"与"认知" | L1×E0 升级率 +6pp 实证 | E v1 有缺陷(E v2 修正中) |
| L5 指标修正纪律 | 指标错误判死有效模型 | 恢复率 26.7%→50.2% | 需人工复核 |
| Radar-Quota 分配 | 单分排序坍缩 | 双雷达均衡 | RA 代理待校准 |
| Calibration Library | 无失败模式记忆 | 4 案例防重复犯错 | 样本<10 未定 v4 |
| Human Overlay | 机器/人工状态割裂 | 双状态并行可溯 | 依赖人工持续使用 |

## 6. 项目功能

核心功能:
- 全市场扫描(5000→2868 排雷池)
- L/E 双状态标注(A 级 551)

- Reverse DCF 演示

## 7. 具体使用方法

```bash
source .venv/bin/activate
# 每日三命令
python tools/run_research_scan.py              # ① 扫描 (~2min)
python tools/build_daily_research_book.py      # ② Book (~1min)
python tools/decision_cli.py --book output/research_book_YYYYMMDD.csv  # ③ 判断
# 快速单条判断
python tools/decision_cli.py --quick "600338,WATCH,理由,反证,Q3" --name 西藏珠峰
# 事件采集
python tools/daily_event_collector.py --top 30 --shadow
# Overlay 状态
python tools/validation_overlay.py --status
```

输出样例: output/research_book_*.md(总览表含 L/E v1/E v2/P/优先级), data/ledger/decisions.jsonl
常见问题: 数据未更新→跑 tdx_financials.py; 断言失败→检查披露日; 北交所慢→已修(缓存)

## 8. Agent 编排方案（PDR 产出工作流）

### 8.1 产出目标
一份可审计的完整 PDR 文档: 背景/工具/设计/架构/创新/功能/使用/编排, 所有结论带证据来源。

### 8.2 子 Agent 角色

| Agent | 职责 | 输入 | 输出 |
|---|---|---|---|
| S1 勘察员 | 盘点代码/数据/文档真实状态 | git/文件系统 | 事实清单(版本/规模/模块) |
| S2 背景分析员 | 痛点/场景/边界 | 事实清单+用户访谈 | 背景章节 |
| S3 架构梳理员 | 分层/数据流/时序 | 代码阅读 | 架构图+模块表 |
| S4 验证审计员 | 核验每个结论(跑测试/查数据) | 各章节草稿 | 校验报告(✅/❌) |
| S5 文档撰写员 | 汇总成稿 | S1-S4 | PDR 完整稿 |
| S6 终审员 | 一致性/缺口标注 | 终稿 | 定稿+信息缺口清单 |

### 8.3 消息传递与校验
S1→S2→S3→S4→S5→S6 线性; 每节点输出须含来源引用; S4 校验不通过→退回对应 Agent; 冲突信息(如版本不一致)→以代码为准并标注。

### 8.4 失败重试
S1 数据缺失→明确"信息缺口"而非编造; API 失败→重试3次后降级; 逻辑矛盾→标记待人工确认。

# Industry Context Layer v1 — 行业上下文层（设计冻结）

**状态**: 设计文档（2026-09-02）— 先设计后开发（避免 L5 v1"先写模型再改定义"的教训）
**依据**: Calibration Prototype v1 六样本 — 5 个分歧中 4 个指向同一缺口：**行业维度确认缺失**

---

## 一、核心命题

> 当前价格下跌，是公司问题，还是行业问题？

公司层"没坏"与行业层"正在恢复/恶化"存在**时间尺度错配**：

```
公司探针（季度财务）: 滞后于价格
行业价格/供需:        领先于财务
→ 融捷案例: 公司营收+402%（锂价滞后反映），但行业供给过剩（前瞻信号）
```

## 二、架构（独立层，不塞进 L5 评分）

```
              Research State Machine
                        |
        ---------------------------------
        |                               |
 Business Layer                Industry Context Layer（新增）
 探针/财务/订单                三模块状态判定
        |                               |
        --------------------------------
                        |
               Lifecycle Decision（Gate 逻辑）
```

**设计原则**：Industry Context 是 L5 的 **Gate（降级/确认）**，不是加权分。

## 三、三模块定义

### Module 1: Cycle Turning（周期拐点）— 对应 000425 徐工

**问题**: 公司订单改善，但行业需求是否回暖？

| 变量 | 来源 | 可行性 |
|---|---|---|
| 行业收入 YoY 中位数 | tdx 财务聚合（SW1，n≥5） | ✅ 31 行业 |
| 行业利润 YoY 中位数 | 同上 | ✅ |
| 行业 RPS 环比变化 | 成分股 RPS 中位数 Δ | ✅ 30 行业（用变化量，非水平） |
| 行业成交/涨幅 | 价格数据聚合 | ✅ |

**输出**:
```
TURNING_UP:   行业收入 YoY > 0 且 RPS 环比上升
STABLE:       收入持平 ±5%
TURNING_DOWN: 收入 YoY < -5% 或 RPS 环比下降
```

### Module 2: Valuation Regime（估值体系）— 对应 603486 科沃斯

**问题**: PE 下降是错杀，还是市场在重新定义该行业/公司的估值中枢？

| 变量 | 来源 | 说明 |
|---|---|---|
| 行业 PE 分位轨迹 | 成分股 peTTM 聚合（历史 3 年分位） | 行业整体估值中枢是否下移 |
| 行业盈利质量 | 行业 ROIC 中位数趋势 | 盈利质量是否支撑原估值 |
| 成长性变化 | 行业收入增速 3 年趋势 | 增长中枢是否下移 |

**输出**:
```
NORMAL_DISCOUNT:  估值回落但盈利质量未变（错杀候选）
OVERREACTION:     估值回落快于盈利回落（错杀候选）
STRUCTURAL_DE_RATING: 盈利质量或成长中枢下降（估值重估，L5 降权）
```

### Module 3: Industry Health（行业健康）— 对应 002192 融捷

**问题**: 公司经营良好，但行业供需结构是否已恶化？

| 变量 | 来源 | 说明 |
|---|---|---|
| 行业价格趋势 | 商品价格/行业指数（如有） | 锂价/铜价/水泥价等 |
| 供给扩张 | 行业 CAPEX 中位数 | 产能过剩风险 |
| 需求趋势 | 行业收入 YoY + 下游数据 | 需求中枢 |
| 盈利分布 | 行业利润 YoY 中位数 + 亏损面 | 行业整体盈利状态 |

**输出**:
```
HEALTHY:        供给/需求平衡，盈利改善
WARNING:        价格下行或供给扩张，需观察
STRUCTURAL_DAMAGE: 供给过剩 + 价格中枢下移（假错杀预警）
```

## 五、Gate 逻辑（L5 v2 候选）

```
L5 Candidate（v1 判定不变）
    ↓
Industry Context Gate:
  Cycle Turning = TURNING_UP      → L5-A（高置信恢复）
  Cycle Turning = STABLE          → L5-B（观察）
  Valuation Regime = STRUCTURAL_DE_RATING → L5-B（降级）
  Industry Health = STRUCTURAL_DAMAGE    → Recovery Trap（标记，不推荐）
```

**不是**: `L5_score += industry_score`
**而是**: 状态门控降级 + 特殊标记

## 六、历史验证协议（Step 8.2-8.4）

```
Step 8.1  定义字段（本文档）
Step 8.2  历史回测: 2022-2025 采样日重建行业上下文
Step 8.3  评估指标（对比 L5 v1 基线）:
          L5 恢复率 ≥ 50.2%（不得下降）
          Recovery Efficiency 提升（基线 53%）
          错误恢复率下降（基线 8.7%）
          覆盖率不下降（不可因行业数据缺失大量丢样本）
Step 8.4  通过 → 进入 State Machine v3；不通过 → 维持 L5 v1
```

**验证原则**: 行业层字段必须可 PIT 构建（只用当日及之前数据）；行业聚合需 n≥5 防单股主导。

## 七、数据缺口（诚实声明）

| 变量 | 状态 |
|---|---|
| 行业财务聚合（收入/利润 YoY） | ✅ 可行（31 行业） |
| 行业 RPS 环比 | ✅ 可行（30 行业，用变化量） |
| 行业 PE 分位轨迹 | ✅ 可行（peTTM 聚合） |
| 行业 ROIC 趋势 | ✅ 可行 |
| **商品价格（锂/铜/水泥）** | ⚠️ 需新数据源（akshare 现货价） |
| 供给/产能数据 | ⚠️ 需手工维护（先做重点行业） |
| 政策状态 | ✅ 人工黑名单机制（已有地产先例） |

**v1 实现范围**: 用可 PIT 构建的财务+RPS 变量实现三模块的简化版；商品价格/产能等作 v1.1 增强。

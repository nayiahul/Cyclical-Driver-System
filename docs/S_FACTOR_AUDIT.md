## 二、核心问题：S1 覆盖率仅 9.9%（170/1720）

### 原因链（代码审计）

```
S1 需要: deducted_profit_yoy (扣非同比) 非空
  + 近 3 季 yoy 线性回归 R²>0.6 (战略行业放宽 0.4)
  + 低基数过滤 (去年同期扣非 < 1000万 → 跳过)
  + 波动过滤 (10季 yoy std > 150pp → 跳过)
```

1. **TDX 字段缺失**: 早期报告期 deducted_profit_yoy 大量 NaN（覆盖率本身受数据历史限制）
2. **R²>0.6 过严**: 周期股利润非线性（V 型反转）→ 线性拟合差 → 被剔除
3. **低基数过滤**: 刚扭亏/导入期公司被排除（正是 Discovery 想要的标的！）

### 影响

- Composite 中 S1 权重 30%，但 90% 股票 S1=NaN → 大量 fallback 到纯动量分支
- **Discovery 引擎的核心信号实际上"形同虚设"**（与 Baseline A 审计结论一致：7% S1>0）

## 四、Phase 2 验证要点（S1 专项）

1. **S1 低覆盖率是数据缺失还是定义过严？**
   - 拆分: 因 yoy NaN 被排除 vs 因 R² 被排除 vs 因低基数被排除
2. **S1 定义是否适合周期股？**
   - 周期拐点（V 型）不是线性加速 → 需要"拐点检测"（单季同比转正 + 环比改善）而非 R²>0.6
   - 这正是 Discovery Engine 的盈利拐点信号改进方向（pit/discovery_interface.py EarningsInflection）
3. **S1 在 PIT 后是否还有预测力？**
   - 170 只样本的 IC 检验（样本小，需注意显著性）

## 五、结论

- **S1 是"想法对、实现不匹配"的典型**: 利润加速是正确方向，但线性回归 + 严格 R² 不适合 A 股周期盈利模式
- **S2/S5/S7 覆盖率健康**，可支撑 Confirmation/质量层
- **RPS/行业动量覆盖全量**，是 Confirmation 核心
- 优先级: Phase 2 验证 RPS/行业动量有效性（Confirmation）→ 再改进 S1 为拐点检测（Discovery）
